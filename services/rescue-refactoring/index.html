Как выглядит проблемный код на Битрикс

  • Раздутый `init.php` на тысячи строк с глобальными функциями и костылями
  • Прямые сырые SQL-запросы в обход механизмов безопасности Битрикс
  • Правки файлов ядра (`/bitrix/modules/`), ломающие системные обновления
  • Неиндексированные запросы, намертво вешающие базу при пиковом трафике
  • Скрытые бэкдоры и уязвимости, оставленные непроверенными подрядчиками

// Раздутая глобальная функция в init.php
function getBadCatalogItems($IBLOCK_ID) {
  global $DB;
  // Уязвимость SQL-инъекции + отсутствие кэширования
  $res = $DB->Query("SELECT * FROM b_iblock_element WHERE IBLOCK_ID=".$IBLOCK_ID);
  while($row = $res->Fetch()) {
    $arResult[] = $row;
  }
  return $arResult;
}
✓ Чистый стандарт D7 ORM (Стало)
namespace Local\Catalog;
use Bitrix\Iblock\ElementTable;

class ServiceManager {
  public static function getActiveItems(int $iblockId): array {
    return ElementTable::getList([
      'select' => ['ID', 'NAME', 'CODE'],
      'filter' => ['=IBLOCK_ID' => $iblockId, '=ACTIVE' => 'Y'],
      'cache'  => ['ttl' => 3600]
    ])->fetchAll();
  }
}
